# 贡献缺口 7 维度检查清单

检查源码时按此清单逐项取证。每个维度的回答必须落到具体文件和函数。未找到实现 = 缺失，不是「可能有」。

先从入口、公共 API、错误路径、测试目录这几处下手，再跟调用链往下读。不要改用 Agent 专用七层（规划、多 Agent、tool 路由等）；那是 `agent-oss-contribute` 的清单。

---

## 1. 错误处理与可观测性

检查失败时调用方和运维能否看懂发生了什么。

检查：

- 失败路径是吞掉异常、裸抛，还是带上下文的错误类型？
- 关键失败是否有日志、指标或 trace？级别是否把可重试和不可重试混在一起？
- 调用方能否根据错误类型决定重试、降级或直接失败？
- 若完全没有统一错误类型：最小改造应挂在现有入口的哪一层？

取证方向：`error` / `Error` / `wrap` / `logger` / `metrics` / `trace` / `sentry`。

---

## 2. API 与兼容性

检查公共边界是否稳定，内部改动会不会无说明地打破调用方。

检查：

- 公共导出是否有明确边界（包入口、导出列表、稳定模块）？
- 有无 deprecation 或版本说明？破坏性变更是否直接出现在补丁路径上？
- 内部类型、未文档化的字段是否泄漏成事实上的公共 API？
- 若边界含糊：收紧导出或补兼容层的改动点在哪，且能否不改现有调用签名？

取证方向：`__init__.py` / `index.ts` / `lib.rs` 的 `pub` / `exports` / `deprecat` / changelog 中的 breaking。

---

## 3. 测试与回归

检查核心路径改完后，维护者能否靠现有测试发现回归。

检查：

- 核心路径有无单测或集成测试？只测 happy path，还是覆盖失败分支？
- 空输入、非法输入、依赖失败有无用例？
- 回归是否只能靠手工跑 README 示例？
- 若没有测试：最小可用用例能复用哪些现有 fixture，预计几个文件？

取证方向：`tests/` / `*_test.go` / `*.spec.ts` / `fixture` / CI workflow。

---

## 4. 配置与扩展点

检查新增一种行为是否必须改核心分支。

检查：

- 关键行为是硬编码，还是配置、接口或注册表可替换？
- 有无清晰扩展点（hook、interface、plugin、middleware）？职责是否写清？
- 新增一种实现时，是否要改多处 `if/else` 或复制粘贴？
- 若没有扩展点：现有入口上最小的注册点应加在哪个函数？

取证方向：`config` / `options` / `plugin` / `hook` / `interface` / `registry` / `middleware`。

---

## 5. 文档与贡献者体验

检查新人能否按仓库自己的文档跑起来并知道怎么改。

检查：

- README / CONTRIBUTING 是否覆盖安装、最小示例、测试命令？缺哪一步会卡住？
- 示例、错误说明是否和当前源码一致（命令、默认值、导出符号）？
- 公共行为变更有没有对应文档位置，还是只改了代码？
- 若文档过时：最小补丁应改哪一页，而不是重写整站文档？

取证方向：`README.md` / `CONTRIBUTING.md` / `docs/` / `examples/`。

---

## 6. 性能与资源边界

检查热路径或外部调用有没有明显的无界成本。

检查：

- 热路径是否重复 IO、无界内存增长、或逐条请求（N+1）？
- 外部调用有无超时、分页、批量或并发上限？还是一次拉全量？
- 缺的是具体上限/超时，还是缺基准因而无法判断？
- 若要改：改动能否限制在一个调用点，而不重写数据模型？

取证方向：`timeout` / `limit` / `cache` / `batch` / `pool` / `pagination` / `sync.Pool`。

---

## 7. 安全与输入校验

检查不可信输入和秘密是否被当成可信数据。

检查：

- 外部输入（路径、命令、URL、反序列化、查询）在使用前是否校验或转义？
- 密钥、token、凭据是否可能进入日志、错误信息或仓库？
- 默认权限是否过宽（任意文件、任意命令、任意重定向）？
- 若缺失：最小校验应加在哪个解析函数，而不是在每个调用点复制？

取证方向：`validate` / `sanitize` / `filepath` / `subprocess` / `shell` / `secret` / `token`。

---

## 取证写法

现状描述至少包含：

```
`path/to/file.py` 中的 `function_name`
```

一条证据不够时再补调用链上下游各一处。不要用「核心模块」「主流程」代替路径。
